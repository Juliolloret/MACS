Adding new data for a machine-learning (ML) model - beginner friendly steps

This checklist explains how to add more data to an ML model in a safe and
repeatable way. The goal is to avoid breaking the model or introducing noisy
results.

1. Understand the goal
   - What question should the model answer?
   - What label or target does it predict? Example: "spam" vs "not spam".

2. Collect and inspect the new data
   - Confirm the file type (CSV, JSON, database table, etc.).
   - Check a few rows to make sure columns look correct.
   - Note missing values, weird units, or unexpected text.

3. Clean the data
   - Remove duplicates.
   - Fill or remove missing values.
   - Standardize units (e.g., convert cm to m).
   - Fix obvious typos or invalid entries.

4. Define features and labels
   - Features are the inputs (numbers or text) the model learns from.
   - The label is the output the model tries to predict.
   - Make sure the new data uses the same feature names and label format as the
     old training data.

5. Apply the same preprocessing steps
   - If you used scaling, tokenization, or encoding before, apply the same
     steps to the new data.
   - Keep the pipeline consistent so old and new samples behave the same.

6. Combine or version the dataset
   - Option A: Append the new rows to the old dataset.
   - Option B: Save as a new version (recommended for traceability).

7. Retrain or update the model
   - If the model supports incremental learning, add the new data in batches.
   - Otherwise, retrain from scratch using the combined dataset.

8. Evaluate the updated model
   - Use a test or validation set that includes some of the new data.
   - Compare metrics (accuracy, precision, recall, etc.) to the previous model.

9. Save and document the change
   - Save the trained model artifact with a new version name.
   - Record what data was added and when.
   - Update any config files or documentation that reference the model.

10. Deploy and monitor
    - Deploy the new model version.
    - Monitor its performance for drift or unexpected behavior.

Tip: Always keep a backup of the old model and dataset. If the new data causes
worse results, you can roll back quickly.
